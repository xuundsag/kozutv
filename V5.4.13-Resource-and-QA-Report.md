# kozuTV V5.4.13 — resource and QA report

## V5.4.13d addendum — regional dubs and Chinese audio

**Regional dub discovery.** Multi-audio masters publish every dub inside one stream while their label names no language ("1080P | Multi Audio"). Such masters were previously only probed when a language bucket already existed, and a hardcoded rule dropped the one Nitro master that carries Naruto's dubs. Both are fixed: multi-audio masters are probed first, an empty scrape is retried instead of being cached as "no dubs", and Chinese/Cantonese join the wanted dub list. Verified live in the player at 390×844:

| Title | Audio menu |
|---|---|
| Naruto (MAL 20) | Japanese, English, Hindi, Tamil, Telugu, Malayalam, Bengali |
| Attack on Titan (MAL 21) | Japanese, English, Hindi, Tamil, Telugu, Malayalam, Kannada |
| Demon Slayer (MAL 5114) | Japanese, English, Hindi |

Naruto's Hindi stream plays (23:37 runtime, media clock advancing). Availability is bounded by what the upstream scrapers publish; languages no source carries are never invented.

**Chinese audio identity.** zh-Hans, zh-CN, chi, zho, cmn, 中文, 普通话 and Mandarin collapse to one `zh` bucket shown as **Chinese (Mandarin)**; Cantonese/粤语/yue becomes **Chinese (Cantonese)**. A label containing "subtitles/sub" is never promoted to an audio track.

**CJK captions.** Punctuation tokens arrive with unreliable timestamps and used to stretch a Chinese cue far past its window; they now only extend a cue when they are adjacent. Unpunctuated Chinese is split into caption-sized pieces at clause boundaries, and Chinese AI caption rows are named per spoken variety.

All 26 test suites pass, including the new `npm run test:dubs` gate.

## Release status

V5.4.13 is deployed. Existing providers are retained as requested, but they do not prove whether each audio recording is an official dub. Filtering labels such as “fan dub” or “AI dub” does not establish that unmarked sources are official. **This release does not guarantee official-only audio**, and no unverified source is represented as verified or official.

All results below are observations, not capacity guarantees. The test host reported Node.js 20, two logical CPUs and approximately 1.94 GiB RAM. It used NVIDIA's hosted service; no local NVIDIA GPU was measured or required for these tests.

### Separate direct NVIDIA concurrency check

A separate client opened **40 concurrent client-side Parakeet streaming RPCs**, fast-feeding the same 4.152-second English WAV to each. All 40 completed successfully with the expected normalized sentence and word timestamps. Wall time was 3,574 ms; RPC p50/p95/max were 3,503/3,554/3,556 ms. Client CPU was 0.704 seconds; RSS rose from 58.25 to 77.92 MiB. These are client-side in-flight calls, not proof of simultaneous processing inside NVIDIA's service. It was a short identical-fixture test, not continuous playback or a multilingual accuracy benchmark.

The workload measurements above were recorded before the final native-track safety, small UI/timing adjustments and the TOML dependency override; those changes were covered by the later regression and live checks, but the 100/40 load tests were not rerun after them.

## Caption timing and quality

- In the updated player, a real Perman episode 2 Hindi HLS window at 132 seconds returned four NVIDIA cues in 3,165 ms. After deployment, the production API returned four cues in 3,526 ms; a concurrent browser check displayed the 132–133.82-second cue at player time 132.91 seconds and prefetched the 144-second window without page errors. The browser check shared or used cached work, so its latency is not an independent provider benchmark. These spot checks show the path functioning, not ground-truth word-timing or transcription accuracy.
- A synthetic HLS extraction fixture placed two speech starts at 5 and 13 seconds; decoded starts measured 5.0213 and 12.9973 seconds. This tests extraction alignment, not word-level ground truth. Across recent deterministic browser tests, a nominal 5–7 second cue appeared at about 4.83–4.86 and disappeared at about 7.01–7.04 seconds, reflecting the deliberate 0.18-second early display bias and scheduling granularity.
- Parakeet produces word timestamps for tested English, Spanish and Hindi. One real Hindi result was wrong; accuracy depends on content and model behavior. Hosted Parakeet rejected Bengali language codes in the probes. The hosted Whisper path produced imperfect Bengali text on a standalone audio sample but no word offsets, so Bengali and other Whisper-backed captions use approximate four-second slices. A Bengali HLS track was unavailable for the episode tested, so real Bengali player-stream transcription was not validated; the Bengali gallery example uses a mock. Real Tamil/Telugu samples included repetitions and errors. Hinglish/Benglish are transliterations, not translations. No representative, annotated multilingual accuracy evaluation was run.
- A later live Hindi → Tamil → Hindi source-switch smoke test returned cued results for the requested Hindi and Tamil windows and showed the corresponding menus, with no browser page errors. The Tamil text remains approximate and was not accuracy-validated.
- A separate live source advertised as English returned Japanese-script text from the multilingual model even when English was requested. This suggests either incorrect source metadata or model misidentification; it is not proof of the actual audio language or of dub provenance. A conservative guard now rejects an entirely non-Latin, sufficiently long model result for a Latin-script selected language. The real probe then returned 422 `audio_language_mismatch` rather than displaying those Japanese characters as English captions. On that error captions are turned off with a warning rather than automatically selecting an English subtitle. The guard is deliberately narrow and can miss mismatches or flag code-switching; it is not a language detector or provenance verifier.
- Seek/source changes cancel or disregard stale AI work. If audio identification or transcription otherwise fails, the player attempts matching existing captions and informs the viewer; if none match, captions turn off. Unsupported HLS formats and unidentifiable embedded multi-audio streams are not guessed. Initial requests, seeks, service latency and model errors can still cause late or missing captions.

## Quotas, workload and costs

The application defaults are **1,800 transcription endpoint requests per socket IP per hour** and **6,000 globally per hour**. These limits count requests, including failed requests and cache hits. The player prefetches; seeks and retries can add requests. A reverse proxy can make many viewers share one socket IP because the app uses the socket address, so the per-IP limit may apply to the group.

At one new 12-second window per viewer, 40 distinct viewers would make approximately **12,000 endpoint requests/hour** before seeks and retries. That exceeds the global default; if all share one socket IP, it also exceeds the per-IP default. With fresh counters and an ideal steady rate, the 6,000 global allowance would be reached in roughly 30 minutes, or the shared 1,800 IP allowance in roughly 9 minutes; startup prefetch and other traffic can shorten this. These are arithmetic estimates, not a sustained test. Cache sharing can reduce actual model requests, but it does not bypass the endpoint counters.

Each interior extraction includes up to 1.5 seconds of context on either side, making roughly 15 seconds of submitted audio per 12 seconds of unique playback. At 40 fully active, uncached viewers this can approach **50 audio-hours submitted per wall-clock hour**, before retries; silent-window skipping and clip ends can reduce it. Whisper divides windows into up to four model requests, so its RPC count can be much higher than the number of endpoint windows. Provider billing rules and current prices were not measured; these audio-time figures are workload estimates, not a cost quote. Do not raise limits without verifying NVIDIA's quota, terms, billing and a spending cap.

The server bounds extraction to four concurrent FFmpeg processes and model work to 40 concurrent jobs, with finite queues and timeouts. Anonymous users are not authenticated merely by the same-origin check. A public installation needs an appropriate authenticated proxy, abuse controls, monitoring and a spending alert.

## Privacy and installation

Audio is transmitted to NVIDIA when AI captions are active; the setting is on by default, and anime subtitles or saved preferences may activate captions automatically. The player shows an AI audio-sharing notice. Turn **AI Transcription** off to avoid this transmission and use matching existing captions where available. The server caches a bounded set of transcript results in memory for five minutes and does not intentionally write extracted audio to disk. Verify rights and NVIDIA's terms before transmitting content. Keep the API key outside the project, release archives and browser; the README describes supported key-file configuration. The API key, runtime profiles, uploaded files and previous releases were not copied into the test evidence.
