# V38 — Hindi audio from Vidwave (partial, not deployed)

Naruto and other anime start with MegaPlay for Japanese/English. Hindi is discovered asynchronously through Vidwave; if its media URL is reachable, Hindi is added to the audio menu. Selecting Hindi switches the existing Video.js player to the Vidwave source through Kozu's signed media proxy. Selecting Japanese/English switches back to MegaPlay; Hindi remains selected on episode navigation and reload. Other regional audio remains on existing resolvers. Hindi discovery validates the upstream media response; a source link that immediately returns 403 is not advertised as playable. Explicit unavailable selections show retry and Use MegaPlay (Japanese) options. Validated discoveries are briefly cached; concurrent duplicate probes are deduplicated.

Real local Playwright tests: Naruto episode 1 MegaPlay Japanese -> audio menu Hindi -> Vidwave HLS playback -> Japanese MegaPlay; Naruto episodes 1 and 2 Hindi, episode list navigation and reload. Solo Leveling episodes 1 and 2 were tested in V37; the V38 discovery uses the same resolver with added reachability check. Report submission passed against the configured database and test record was removed.

Important unresolved limitations: Vidwave's documentation advertises backup, but actual requests for Naruto, One Piece, and Solo Leveling returned HTTP 400 'Invalid source! Currently, only main server is allowed.' One Piece AniList 21 episodes 1, 2 and 50 resolve to NestZone HLS links that return 403 'This stream link only works on NestZone' in this environment; the official Vidwave player also failed for One Piece here. No working Vidwave Hindi source for these One Piece episodes has been verified. The test build hides Hindi when its upstream check fails; that does not mean a Hindi dub does not exist. Other titles, entire episodes, sound correctness and all controls have not been exhaustively verified. Hindi-only endpoint does not provide Tamil/Telugu etc. Caption issue remains undiagnosed. The V35 watchlist ordering/background-persistence issues remain unresolved. EmbedWave is no longer a selectable server but is still used internally by existing fallback/audio/subtitle code. This archive contains the actual .env and must remain private. No deployment is claimed.
