# V24 — community comments and reaction icons

- Comments on watch pages appear after episodes for series and directly after movie reactions. Discussions are **per title**, shared across episodes. They use plain text, not rich-text formatting or attachments. Signed-in users can post and reply, like/dislike comments, and delete their own comments; deleting a comment also deletes its replies. Visitors can read comments without signing in. Root comments can be sorted recent/top and loaded in pages; replies are loaded in batches. Comment and vote data lives in PostgreSQL. Login/session and existing account state remain unchanged.
- New additive tables media_comments and media_comment_votes are created automatically by database initialization. Existing user/state tables are not dropped or overwritten. During testing these two empty schema tables were created in the configured database; only temporary test accounts and their comments were inserted and removed.
- Comments use escaped plain text, a 2,000-character maximum, same-origin write checks, sign-in requirement, and a basic in-process posting limit. There is no administrator moderation/reporting system, attachment support, rich-text toolbar, or spoiler-hiding feature yet. Public deployment needs an appropriate moderation plan.
- Replaced player reaction glyph with a white Lucide-inspired thumbs-up outline (Lucide icons, ISC license, https://lucide.dev/icons/thumbs-up); dislike uses rotated shape. Selection remains white/filled. Comments follow the reference layout in KozuTV dark/orange styling.
- Asset versions changed and essential shell worker bumped to kozutv-v8. Comments API bypasses CacheStorage.

## Tests
Browser tests at 320, 390, 768, and 1280px verified screenshot layouts, no horizontal overflow, reply/post/vote interactions, escaping and movie positioning. 390/1280 tests checked comments below episodes; player positioning and rapid-reaction tests passed. Against the configured PostgreSQL database, tests verified posting/replying, voting, author identity, ownership, delete cascades, guest rejection, cross-title validation, and reply pagination, using temporary accounts which were deleted. Viewer, account-state integration, One Piece arcs, and anime selector tests passed. Screenshots use fictional mocked users and content.

## Deploy safely
This full ZIP includes actual .env credentials: keep private. Production has not been deployed by the build author. Back up the destination .env and data/ first. Do not overwrite live data/states.json or data/user.json. Example after extraction: `rsync -a --exclude 'data/states.json' --exclude 'data/user.json' moscowtv_v5419/ /path/to/app/`. This overwrites destination .env unless excluded separately. Then `npm install --omit=dev`, `chmod 600 .env`, `node scripts/doctor.mjs`, and restart. The configured database user needs CREATE TABLE/INDEX permission for the additive migration; database failure displays an unavailable message rather than pretending comments were posted. Verify production `/sw.js` reports kozutv-v8 and test comments after deployment. See CHANGELOG-v21.md for earlier changes.
