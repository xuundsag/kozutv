# V37 — Vidwave native-player integration (partial, not deployed)

Vidwave Hindi anime can be selected under player settings > Quality and servers > Vidwave (Hindi). It is resolved server-side and delivered via the existing signed media proxy to the existing Video.js and MegaPlay controls; it is not an iframe. Switch back using the MegaPlay entry. A retry/fallback button is shown if Vidwave cannot load. The selection is included in the watch URL and retained on episode changes. EmbedWave is no longer a selectable movie/TV server; existing internal resolution and subtitle fallback logic still uses EmbedWave. Vidwave's available service does not provide a verified replacement for movies/TV.

Verified locally with real upstream Solo Leveling AniList 151807/MAL 52299: episodes 1 and 2, phone-size native Video.js via proxy, server switching, actual quality source switching to 480p, seek, pause/resume, intro skip, episode selection, fullscreen, 1.5x speed, and more than 70 seconds of video time. Desktop browser playback was also checked. Report submission was retested against the configured private database; test record removed. Test screenshots are external to this archive.

Known limitations: this is not fully verified across titles or networks. One Piece AniList 21 episode 1 resolved an HLS URL but its upstream returned 403 in this environment; the provider's own embedded player also did not start it. Error/retry/fallback UI appears; live successful recovery for that title was not verified. Vidwave may be intermittent or change its protocol. Vidwave does not provide a verified drop-in movie/TV source. Captions issue has not been diagnosed; the tested Vidwave Solo Leveling source returned no subtitle tracks. V35 optimistic watchlist writes may be reordered on rapid toggles; server-side background write guarantees remain unfinished. Service worker is now kozutv-v37. No deployment is claimed. The archive contains the real .env and must remain private.
